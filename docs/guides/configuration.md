# Configuration

## Per-org settings (`.env.<org>`)

`npm run setup` creates one `.env.<org>` file per org. These files are
gitignored: never commit them.

| Variable | Required | Description |
| --- | --- | --- |
| `VAPI_PRIVATE_API_KEY` | ✅ | The org's private API key, from [Private API Keys](https://dashboard.vapi.ai/org/api-keys). The older name `VAPI_TOKEN` is also accepted. |
| `VAPI_MAX_GITOPS_RPM` | | Override the org’s GitOps client request ceiling, in requests per minute. Positive integer; defaults to `maxGitopsRpm`, then 100. |
| `VAPI_BASE_URL` | | API base URL. Defaults to `https://api.vapi.ai`; EU orgs use `https://api.eu.vapi.ai` (`npm run setup -- <org> --region eu` sets it). |
| `VAPI_CREDENTIAL_<NAME>`, `VAPI_PHONE_NUMBER_<NAME>` | | Generated by `setup` and `pull` inside a marked block: the org's credential and phone-number IDs, by name. Values you set outside the block are kept and take precedence. |

A variable already set in your shell or CI environment takes precedence over
the file. `.env.<org>.local` and `.env.local` are also read, after
`.env.<org>`, and only fill in variables that are still unset.

### Keys in your shell

Commands look for an org's key in this order:

1. `VAPI_PRIVATE_API_KEY_<ORG>`: the org name upper-cased, with hyphens as
   underscores (`acme-dev` → `VAPI_PRIVATE_API_KEY_ACME_DEV`).
2. `VAPI_PRIVATE_API_KEY` (or `VAPI_TOKEN`) in the environment.
3. `VAPI_PRIVATE_API_KEY` (or `VAPI_TOKEN`) in `.env.<org>`.

To keep keys in your shell profile, export one `VAPI_PRIVATE_API_KEY_<ORG>`
per org. Don't export `VAPI_PRIVATE_API_KEY` there: it applies to every org,
so one org's key would be used for all of them. When the generic variable
overrides a different key in `.env.<org>`, commands print a warning and
`npm run setup` refuses to continue. Setup also refuses a key that another
org's `.env` file already holds.

## CI and workflow settings

Set these in GitHub under **Settings → Secrets and variables → Actions**.

| Name | Kind | Used by | Description |
| --- | --- | --- | --- |
| `VAPI_PROMOTION_TOKENS` | Secret | [Promotion](promotion.md) | JSON map of org name to private API key, for example `{"dev":"…","prod":"…"}`. |
| `VAPI_PROMOTION_ENABLED` | Variable | Promotion | `true` to promote automatically after changes land on `main`. |
| `VAPI_CHECK_TOKENS` | Secret | [PR checks](pr-checks.md) | JSON map of org name to private API key, for checks that run in several orgs or a CI org. |
| `VAPI_PRIVATE_API_KEY` | Secret | PR checks | A single org's key, when every check runs in one org. |
| `VAPI_CHECKS_ENABLED` | Variable | PR checks | `true` to run PR checks. The workflow does nothing without it. |

## Configuration files

| File | Purpose |
| --- | --- |
| `promotion.yml` | Promotion pipelines between orgs. Start from `promotion.example.yml`. |
| `vapi-checks.yml` | PR checks. Start from `vapi-checks.example.yml`. |
| `resources/<org>/.vapi-org.json` | The Vapi org ID and optional `maxGitopsRpm` client ceiling (default 100). Written by the first command that can see the key's org, then checked by every command before any request: a key for another org stops the command. If a folder genuinely moves to another org, delete the file in a reviewed commit. |
| `resources/<org>/.vapi-ignore` | Platform resources this repo shouldn't manage, as glob patterns. See `resources/.vapi-ignore.example` and [YAML conventions](../learnings/yaml-conventions.md). |

## Other environment variables

| Variable | Description |
| --- | --- |
| `CI=true` | Suppresses interactive warnings, such as the one `pull --force` prints. Set automatically by most CI systems. |
| `VAPI_CALL_DEBUG=1` | Makes `npm run call` log message types it would otherwise ignore. |
| `VAPI_GITOPS_ROOT` | Overrides the repository root that `npm run promote` and `npm run check` read from. Mainly for tests. |

## max GitOps RPM

max GitOps RPM caps the requests this client sends for an org, including
reads, writes, probes and retries. It is a GitOps client limit, not a Vapi
org limit. Set it in the committed `resources/<org>/.vapi-org.json`:

```json
{ "orgId": "your-org-id", "maxGitopsRpm": 100 }
```

The default is 100 requests per minute, below Vapi's default org API limit
of 200 RPM. Leave headroom for other clients. Values must be positive
integers; an invalid setting stops the command and names its source.
A settings-only file is valid before pinning, which preserves existing fields.

Precedence is shell/CI `VAPI_MAX_GITOPS_RPM`, then `.env.<org>`,
`.env.<org>.local` and `.env.local` (first file wins), then committed
`maxGitopsRpm`, then 100. Quoted values, `export` prefixes and inline
comments work the same way in the env files for every command.

On a 429, the warning names the org and effective RPM, suggests lowering
`maxGitopsRpm` or setting `VAPI_MAX_GITOPS_RPM`, and links to the org API
rate limit: [EU](https://dashboard.eu.vapi.ai/settings/organization) for
`api.eu.vapi.ai`, otherwise
[US](https://dashboard.vapi.ai/settings/organization).
Existing retry backoff and write gaps still apply.

Each org shares one token bucket per process. It refills at
`maxGitopsRpm / 60` tokens per second, with a small burst capacity of
`max(1, ceil(maxGitopsRpm / 60))`. Separate processes do not coordinate,
so their combined traffic can exceed the client ceiling.
